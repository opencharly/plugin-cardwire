# 2026.270.1512 — fix(plugin-cardwire)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Eradicate the schema-less plugin exception for `plugin-cardwire`, an ordered per-repo unit of the R5 cutover tracked in **opencharly/charly#712**.

The SDK contract (**opencharly/sdk#314**, landed) changed `sdk.BuildCapabilitiesWithRequires` to REJECT a `nil` schemaFS and an empty schema: every plugin MUST ship a non-empty, self-contained CUE schema served over `Describe` and spliced `base ++ plugin` at the host load gate. `plugin-cardwire` previously passed `nil` as the schemaFS and served an EMPTY `schema_cue`.

Files (`git diff --stat origin/main...HEAD`):
- `candy/plugin-cardwire/schema/cardwire.cue` — NEW, a package-less, self-contained CUE doc schema defining `#CardwirePlugin` (the `command: cardwire` contract). It references no base def, so it compiles STANDALONE (the SDK's serve-side compile) and splices `base ++ plugin` at the host load gate.
- `candy/plugin-cardwire/plugin.go` — `//go:embed schema/cardwire.cue` → `var schemaFS embed.FS`; `sdk.NewMeta(..., schemaFS)` instead of `nil`; the stale "ships no schema" comment corrected.
- `candy/plugin-cardwire/schema_serve_test.go` — NEW, TWO tests: `TestNewMetaServesNonEmptySchema` and `TestServedSchemaSplicesOntoHostBase` (the real `base ++ plugin` splice).
- `candy/plugin-cardwire/go.mod` (and, on some repos, `go.sum`) — promotes `cuelang.org/go v0.16.1` from `// indirect` to a direct dependency, forced by the new test's `cuelang.org/go/cue/cuecontext` import (same version; no supply-chain change).

**Refs:** opencharly/charly#712
